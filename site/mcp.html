What the tools do

{{MCP_TOOL_COUNT_PHRASE}}

Two calls cover the whole surface. Search resolves a human name — Korean or English — into an ID and a category; the second call takes that pair and returns the data for it.

Names and purposes below are read from the reference table the skills ship, so this page cannot describe a tool the skills no longer call.

{{MCP_TOOL_CARDS}}

What comes back depends on the category you asked for. A mob or an NPC returns animation states as lists of frames, each frame carrying its image path, its origin, how long it holds, and its layer. A character part returns the same plus socket points — navel, neck, brow, hand — which is what lets a body, a head, and a piece of equipment be assembled into one figure instead of three overlapping images. A map returns its tiles, footholds, portals, and spawns. A skill returns its spec together with the visual effect data. Frame images are then loaded from the MSU resource CDN using the path each frame gives; nothing about the file layout has to be guessed, and the skills are explicit that it must not be.

Builder resources, through the MSU Open API

{{MCP_SERVER}} is served by the MSU Open API and returns MapleStory Universe builder resources — the sprite, map, skill, and item data an app is assembled from. It is not a wrapper around the public MapleStory game API, and it does not answer questions about a live account: no character progress, no rankings, no inventory. If that is what you need, this is the wrong server.

The distinction matters in practice because it decides what your agent can build. Resource access is what makes an agent able to render a scene that looks like MapleStory rather than describe one, and it is scoped by the key you were issued as a builder.
